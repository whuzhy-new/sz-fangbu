# 深圳房补地图

用于查看字节跳动深圳三个工区的预估房补范围，并查询小区、地址或地图选点到工区的通勤方案。

[打开地图](https://sz-fangbu.sturdy-sage-7734.chatgpt.site/) · [使用说明（含操作录屏）](https://sz-fangbu.sturdy-sage-7734.chatgpt.site/guide.html) · [办公终点与历史数据](docs/office-endpoints.md)

地图范围已提前计算，浏览时不需要逐点查询路线。选定具体地点后，再使用高德接口核验，展示符合方式、路线和各段时长。

| 工区选项 | 当前计算终点 | 区域 |
| --- | --- | --- |
| 深圳湾 | 深圳湾创新科技中心 **T2 栋** | 科苑、科技园 |
| 景湖 | 景湖大厦 | 后海、创业路 |
| 太子 | 太子广场 | 海上世界、蛇口 |

本项目按下述规则辅助选房。地图估算和应用结论均不能代替公司审批；每月租住 **16 个工作日**等其他要求需另行满足。

## 如何使用

1. **选择实际办公工区。** 步行、骑行、地铁三个图层可分别开关；开关只影响地图显示，不影响路线查询。
2. **选择居住地点。** 输入小区或地址，按 Enter 搜索，再选择结果；也可以点击地图上的地点或空白位置，确认后开始查询。搜索结果有入口坐标时优先使用入口。
3. **查看方案。** 结果逐项返回。点击方案可在地图上查看路线；地铁方案可展开查看分段及计算过程。超过时限的方案置灰，仍可点击。
4. **上高德看路线。** 打开方案的二维码弹窗，在手机高德中查看路线并按申请要求截图。分段方案分别提供进站接驳、站间地铁、出站接驳三个入口。

可拖动标记修正小区门口位置，再重新查询。收藏、最近地点、工区和图层偏好保存在当前浏览器，暂不跨设备同步。

二维码支持系统相机、系统二维码扫描工具及高德 App 扫一扫；微信扫码无法直接打开。手机访问时，也可以点击二维码尝试打开高德。离线使用可[下载 HTML 说明](docs/使用说明.html)后用浏览器打开，录屏和图片已内嵌，无需额外素材文件夹。

## 判断顺序与计算口径

每个地点按当前工区依次查询。步行或骑行达标即结束；地铁方案取整后为 19～20 分钟时，保留该方案并继续比较分段候选。找到 18 分钟及以内的地铁方案，或候选查完、达到查询时限后停止。

| 阶段 | 查询内容 | 满足条件 |
| --- | --- | --- |
| 1 | 全程步行、普通自行车，并行查询 | 步行 ≤30 分钟，或骑行 ≤20 分钟 |
| 2 | 高德「居住地点 → 工区」完整地铁方案 | 接口总时长 ≤20 分钟 |
| 3 | 地铁与两端步行／自行车接驳的分段方案 | 各段取整后相加 ≤20 分钟 |

电动车、摩托车、公交、打车等方式不参与判断。完整地铁方案只接受步行与地铁的组合。

某次请求失败或超时，会保留已返回的方案，再按流程尝试后续查询。**未完成核验不代表不符合条件**，本地模型估算也不能代替高德路线结果。

### 完整地铁与分段地铁

**完整方案**使用高德接口返回的总时长，包含其计入的步行、换乘和候车估算，不自行扣减。

**分段方案**按以下口径相加：

```text
小区门口 → 进站口：步行或普通自行车
进站车站 → 出站车站：高德地铁路段耗时 + 站内换乘步行
出站口 → 办公地点：步行或普通自行车
```

分段计算保留站内换乘，不另加首次进站、最终出站的站内步行或候车时间。高德地铁路段耗时字段不等同于独立的列车运行时刻表。

地面接驳以**地铁口**为起终点；站间地铁以**车站 POI**为起终点，查询与二维码均明确指定首末站，避免用出口坐标查询时混入额外接驳。工区侧会比较多个候选站和出口，深圳湾包含粤海门，并非固定使用最近车站。

这是本项目采用的分段测量口径。申请时需核对公司要求及高德实际页面，多段截图显示的时长可能与 API 返回值不同。

### 分钟取整

当前规则为 **30 秒及以上进一分**，每段最少计 1 分钟：

| 原始时长 | 计入时长 |
| --- | --- |
| 18 分 29 秒 | 18 分钟 |
| 18 分 30 秒 | 19 分钟 |
| 18 分 31 秒 | 19 分钟 |
| 20 秒 | 1 分钟 |

步行、自行车、完整地铁按方案总时长取整；分段地铁**每段先取整，再相加**，含独立展示的换乘段。例如 `3分30秒 + 10分30秒 + 5分30秒` 计为 `4 + 11 + 6 = 21分`。

显示、时限判断、候选筛选与预计算范围采用同一规则；API 原始秒数保留在 `rawDuration` 中。曾试算的 20 秒进位版本仅归档保留，当前未启用。

## 范围图与数据来源

| 内容 | 数据与计算方式 | 用途 |
| --- | --- | --- |
| 底图、工区、车站及出口 | 高德 | 地图展示与定位 |
| 步行、骑行预估范围 | 校准后的 OSM 有向路网，50 米网格预计算 | 选房初筛 |
| 地铁预估范围 | 高德固定站间方案、工区侧接驳，加本地路网估算的居住侧接驳 | 选房初筛 |
| 具体地点的步行、骑行及完整地铁 | 高德路线接口，或有效期内的接口缓存 | 地点核验 |
| 具体地点的分段地铁 | 本地比较接驳候选，再用高德核验选中的接驳，拼接预备固定段 | 地点核验 |

当前 OSM 路网数据日期为 **2026-11-07**，地铁参考出发时刻为 **2026-11-09 09:00**，地图输出坐标为 **GCJ-02**。参考时刻是数据快照，不是实时列车位置或实时到站时间。各工区生成时间记录在 [`coverage.json`](public/data/coverage.json) 的元数据中。

范围图有以下显示处理：

- 平滑外观并羽化边界；约 120 米的边缘区域选点提示「边缘地带，是否满足需核验」。羽化不改变原始判断边界。
- 生成时补全面积不超过 1 万平方米的内部小洞，包括图层叠加形成的小洞；不向外扩大边界。
- 部分较大的住宅空白经高德小区入口核验后补全，依据保存在 [`coverage-corrections.json`](public/data/coverage-corrections.json)。

这些处理不会替代具体地点的路线查询。地图选点距离当前工区三个范围图层的合集超过 **500 米**时，暂不允许确认；图层显隐不影响此限制。

模型验证样本和误差记录见 [`validation.json`](public/data/validation.json)。OSM 可能缺少小区内部道路、通道或通行限制，高德 API 与手机 App 也可能因起终点解析、方案和取整不同而显示不同时间。项目不能保证囊括所有地图软件、所有出口或任意换乘组合。

### 分段查询为何需要本地路网

步行、自行车和完整地铁均未找到符合条件的方案时，服务端才加载路网。从实际坐标分别进行一次步行、一次骑行最短路搜索，计算所有预备站口的接驳，再加上固定地铁和工区侧接驳，比较全部预备组合。

本地比较负责排序，高德每次最多核验 **3 个接驳、每站最多 2 个**，找到符合条件的方案即停止。500 米内最近入口优先核验步行，同站相反方向的邻近入口也保留步行核验机会，以减少骑行绕路造成的遗漏。这不等于逐一调用高德穷举所有方案；本地估算最短时长不会直接产生已确认结论。

结果通过 NDJSON 流逐项返回。单次高德请求独立限时 **8 秒**，完整查询等待预算为 **25 秒**；网络、数据库和主机负载会影响实际响应时间，不保证所有方案在 5 秒内查完。

## 本地运行

需要 **Node.js ≥22.13.0** 和 npm。仓库已包含预计算范围、固定地铁方案和运行时路网，日常运行 WebApp 无需 Python 服务，也无需重新生成数据。

### 1. 安装依赖并配置密钥

克隆仓库后，在项目根目录运行：

```sh
npm ci
```

新建 `.dev.vars`，填写自己的高德开放平台配置：

```dotenv
AMAP_WEB_KEY="你的 Web 服务 Key"
AMAP_JS_KEY="你的 Web 端 Key"
AMAP_JS_SECURITY_CODE="Web 端 Key 对应的安全密钥"
AMAP_APP_MONTHLY_LIMIT="100000"
AMAP_SEARCH_MONTHLY_LIMIT="3000"
```

| 配置 | 作用 |
| --- | --- |
| `AMAP_WEB_KEY` | 服务端地点搜索、地理编码和路线规划 |
| `AMAP_JS_KEY` | 浏览器高德 JSAPI 底图 |
| `AMAP_JS_SECURITY_CODE` | JSAPI 安全模式的服务端代理密钥 |
| `AMAP_APP_MONTHLY_LIMIT` | 应用每月路线请求预算上限，默认 100000 |
| `AMAP_SEARCH_MONTHLY_LIMIT` | 应用每月搜索请求预算上限，默认 3000 |

JSAPI 安全代理以 `/_AMapService` 为一级路由。源码中的 `app/%5FAMapService/` 是框架对下划线路由的转义。Web 服务 Key 和安全密钥留在服务端；Web 端 Key 用于加载浏览器地图。`.dev.vars`、`.env*` 已加入 Git 忽略规则。

预算上限是**本应用的计数限制**，不是高德账号的剩余额度或免费额度承诺。应根据账号实际可用额度设置；应用不购买流量包或自动付费扩容。

### 2. 构建并初始化本地数据库

```sh
npm run build

node --import ./scripts/sites-env.mjs \
  ./node_modules/wrangler/bin/wrangler.js d1 execute DB \
  --local \
  --config dist/server/wrangler.json \
  --persist-to .wrangler/state \
  --file drizzle/0000_heavy_omega_sentinel.sql
```

数据库迁移只需对新建的本地数据库执行一次。D1 保存接口缓存、共享核验结果、调用预算计数和请求间隔记录。

同一工区和起点（入口坐标及高德点位 ID）可复用 7 天内的完整核验结果。点击「重新核验」会重新请求高德；成功后替换旧结果，未完成时保留原结果。共享结果不记录查询者或其自定义的地点名称，工区入口或计算口径变化后会重新查询。

### 3. 启动预览

```sh
npm run dev
```

访问 [http://localhost:5173](http://localhost:5173)。修改应用代码后会热更新。

生产构建完成后，也可运行 `npm run start`，使用 Wrangler 启动本地产物预览，以终端输出的地址为准。

## 运行与部署

应用使用 **React 19、TypeScript、Vinext／Vite、高德 JSAPI**，服务端运行于 **Cloudflare Workers**，使用 **D1** 缓存接口响应。当前通过 **Sites** 托管。

部署配置位于 [`.openai/hosting.json`](.openai/hosting.json)，数据库绑定名为 `DB`。生产环境需配置与本地同名的高德密钥和预算变量，并执行数据库迁移；本地 `.dev.vars` 不会代替生产 Secrets。迁移到自己的 Sites 项目时，需要使用自己的项目 ID 和数据库绑定。

路线响应缓存 **7 天**，地点搜索响应缓存 **30 天**；命中缓存不新增高德调用。D1 使用原子预算计数和全局请求间隔，达到应用预算后停止新增查询，已生成的范围仍可浏览。离线数据脚本另有本地调用账本；其计数与线上 D1 独立，均不代表整个高德账号的使用量。

### 重新生成数据

**普通代码或界面修改无需重新计算范围。** 更改办公终点、路网、校准系数、地铁参考日期或分钟取整规则时，才需要更新对应数据。

离线脚本使用 Python 和 [`scripts/data/requirements.txt`](scripts/data/requirements.txt) 中的依赖，部分脚本使用 Unix 文件锁。可在 macOS／Linux 创建环境：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/data/requirements.txt
```

重建路网需另备广东 OSM PBF，放到 `work/guangdong.osm.pbf`；来源为 [Geofabrik 广东数据](https://download.geofabrik.de/asia/china/guangdong.html)。`work/`、虚拟环境和密钥不进入 Git。

| 任务 | 脚本 | 说明 |
| --- | --- | --- |
| 构建 OSM 路网 | `scripts/data/build_network.py` | 已有路网时跳过，重建前需处理旧工作数据 |
| 骑行校准与模型验证 | `calibrate_bicycling.py`、`validate_network.py` | 使用高德样本；无缓存时会产生接口调用 |
| 准备地铁与接驳候选 | `prepare_rail_plans.py`、`prepare_station_api.py` | 站间证明必须明确首末站，返回站点不一致时拒绝采用 |
| 扩展地铁候选审计 | `expand_rail_candidates.py` | `--cache-only` 只审计，不新增调用、不替换公开数据 |
| 生成范围与服务端索引 | `generate_coverage.py` | 读取已完成的固定方案；拒绝发布未完成的地铁准备结果 |
| 导出运行时路网 | `export_road_network.py` | 路网或权重变更后执行，不调用高德 |
| 调整办公终点 | `retarget_office.py` | 分阶段生成，可检查后再应用，保留旧版本 |
| 调整分钟取整规则 | `rebuild_duration_policy.py` | 需同时更新应用规则与相关数据，避免混用版本 |

表中未重复路径的脚本均位于 `scripts/data/`。这些脚本存在输入、缓存和检查点依赖，维护前需核对当前数据版本；不要把早期初始化脚本直接当作重建当前 T2 数据的一键流程。

原园区入口、首次 T2 入口、30 秒及 20 秒进位版本保存在 `data/snapshots/`，每套含文件校验清单。**工区终点、固定接驳、范围和取整规则应成套使用**。终点调整和历史版本说明见 [`docs/office-endpoints.md`](docs/office-endpoints.md)。
